# 实施决策

## D-001｜空仓库技术栈

- 日期：2026-10-11
- 决策：采用 npm workspaces 组织 React + TypeScript + Vite 前端、Fastify + TypeScript API 与共享 contracts 包。
- 原因：符合 `docs/mvp/05` 的空仓默认方案；不拆分微服务。

## D-002｜本地 PostgreSQL 兼容运行时与媒体 fixture

- 日期：2026-10-11
- 决策：本地开发使用 PGlite（PostgreSQL 兼容嵌入式运行时）执行同一套 SQL 迁移；生产通过 `DATABASE_URL` 接入受管 PostgreSQL 的适配点保留为上线前配置项。媒体 fixture 是代码生成的合成 WAV，文件名和节目标题均标注“开发示例”。
- 原因：当前环境未发现 PostgreSQL 客户端或服务，仍须让本地闭环可运行；不将 fixture 或本地存储宣称为生产内容／对象存储接入。

## D-003｜P1 微信能力

- 日期：2026-10-11
- 决策：默认关闭 `wechatEnabled`；没有账号、域名、JS-SDK 凭证时不提供登录入口和 SDK 卡片接口。
- 原因：P0 游客收听不依赖外部账号，且不能伪造 OAuth 或 SDK 成功。

## D-004｜分析默认值

- 日期：2026-10-11
- 决策：新游客的非必要分析默认关闭；用户可在“收听偏好”中主动开启。播放、队列、喜欢等提供服务所需数据仍仅在服务期间按最小范围保存。
- 原因：以隐私优先方式满足“可关闭且不阻断收听”，并避免把没有同意的听音行为写入长期分析表。
