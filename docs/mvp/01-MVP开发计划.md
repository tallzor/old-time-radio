# 声音时间机器｜MVP 开发计划

版本：v0.1｜编制日期：2026-10-11｜状态：供范围评审与开发拆解，尚未确认排期。

依据：用户提供的《规格说明.md》。本文保留原产品目标，对缺失规则给出建议默认值；所有工期、样本量和指标阈值均为规划假设，不是既有事实或行业基准。原文件不做修改。

## 1. 对产品的理解

面向 65–85 岁老人，用熟悉的收音机形态和真实、可追溯的声音内容，降低数字产品使用门槛。产品价值由三部分共同构成：容易开始听、声音唤起年代记忆、愿意再次回来听。子女可以帮助首次打开或接收分享，但老人本人是主要使用者。

核心闭环：打开 → 点击开始收听 → 调年代或换节目 → 表达喜欢 → 次日主动回来。

首页是收音机，不是内容信息流；“今日电台”是按偏好选播的点播队列，不是直播，也不承诺每天更新。年代沉浸服务于收听，不能用动画和电流声拖延播放。

MVP 必须同时交付：可用的 H5、可播的内容、可信的行为统计、能检验自主使用的试点方法。只有界面演示不能完成验证。

## 2. 原规格中的冲突与建议决策

| 编号 | 原规格情况 | 本版建议默认决策 | 原因与影响 |
|---|---|---|---|
| D01 | 首次选择年代和类型，然后自动播放 | 首页直接提供“开始收听”，年代／类型可选；不强制问卷 | 满足“打开→点击→听”；减少首播前步骤 |
| D02 | 进入首页自动播放 | 首次由用户点击触发；续播允许尝试，受阻则显示开始按钮 | 有声自动播放受浏览器策略影响，不能作为必达承诺 |
| D03 | 喜欢只记行为，但我的包含喜欢内容 | 做最小收藏关系、取消喜欢和列表，并单独记录点击事件 | 保留可见用户承诺；点击次数不能替代收藏状态 |
| D04 | 年代包含今天，类型包含老歌，但内容库与清单未覆盖 | 首发只开放有已上架内容的 70／80／90／00 年代及新闻／评书／小说／戏曲；今天、老歌后置 | 避免空入口；需要恢复时先补内容再启用 |
| D05 | 微信不强制登录，但要求保存偏好、收听数据 | 游客即有匿名身份及数据；微信绑定为 P1 条件交付 | 核心验证不依赖账号资质；账号条件已具备则纳入首发 |
| D06 | 新闻年代、作品年代、录音年代混用 | 按编辑审核的“记忆年代”展示，另外记录事件／创作／录制年份及依据 | 防止把后来的演绎当作当年录音 |
| D07 | 退出时偶尔弹反馈 | 不拦截浏览器退出；只在站内安全时机展示可忽略反馈 | 减少干扰，避免依赖不可控退出流程 |
| D08 | 首批 20 条涵盖多个年代和类型 | 保留 20 条规模，按可用组合分布并标注样本不均 | 不假设 4×4 的每个组合都有内容，不做无数据排名 |

上述是可用于开发的建议基线，尤其 D01、D03、D04、D05 属于对原范围的调整，需产品负责人在 W1 评审中确认；不把它们写成用户已批准的决定。

## 3. 范围与优先级

| 优先级 | 交付项 | 完成标准 |
|---|---|---|
| P0 | 收音机首页、年代／类型选择、播放详情、我的 | 三个主入口；不用登录可完成全流程 |
| P0 | 单一全局播放器 | 开始、暂停、恢复、结束接播、换台、失败重试；切页不重播 |
| P0 | 内容筛选与去重随机选播 | 不出现空节目；候选不足有明确说明；不暗中跨年代 |
| P0 | 游客偏好、喜欢及列表 | 刷新同浏览器后保留；可取消；明确游客保存边界 |
| P0 | 分享基础能力 | 节目深链、产品链接、微信内分享指引及复制兜底 |
| P0 | 轻量反馈与行为事件 | 时长按真实播放增量记录；埋点去重；可导出日报 |
| P0 | 轻量运营工作台 | 上传、编辑、审核发布、下架、排序、CSV 数据导出；仅工作人员访问 |
| P0 | 内容准备 | 20 条通过来源、年代、音质与使用依据审核的可播内容 |
| P0 | 适老化、错误态、隐私说明、基础监控 | 真机验收通过；失败可恢复；事件不泄露身份 |
| P1 | 微信授权登录、游客数据绑定、跨设备保存 | 账号权限与域名配置确认后开发并独立验收 |
| P1 | 微信分享卡片配置 | 依赖 JS-SDK 条件核验；失败保留基础分享 |
| 后续 | 今天频道、老歌、完整连续剧追更、更多动效 | 首轮数据支持后再投入 |
| 不做 | AI 聊天、主动陪伴、商业化、广告、社交、复杂推荐、自动节目生产系统 | 不进入本轮任务池 |

AI 年代播音只属于离线内容制作流程。用户端不实时合成、不克隆知名播音员声音、不把重制音频标成历史原声。

## 4. 内容先行的工作包

20 条来自原清单的“候选题目”，不是已获得的音频资产。原分布是 70 年代 5 条、80 年代 8 条、90 年代 5 条、00 年代 2 条；这种分布会影响偏好分析。

每条登记：标题、展示年代、具体事件或作品、资料出处、录制年份（未知可空）、内容来源类型、音频使用依据、音频文件、秒级时长、审核人、发布状态。连续作品须标明“节选”和片段信息，不承诺下一集。

特别核对：原清单“北京申办奥运相关报道”必须指向具体年份和事件，不可与“北京奥运会”混写；“神舟飞船新闻”“改革开放早期新闻”“春晚戏曲”均需先明确具体内容；不能仅凭作品名称判断录音所属年代。

建议先完成 8 条已审核试播内容供 W2 联调；W4 前补齐 20 条。若取得不到原候选资源，可换同年代同类型的有依据内容，并保留替换记录。若只够更小内容集，可继续内部技术测试，但不宣称完成计划中的 MVP 试点。

每个对外开放组合至少 2 条可播内容为建议上线门槛；不足则合并测试范围、补内容或暂隐藏该组合。对所有类型提供“都可以”，不通过给空组合跳转其他内容伪装匹配。

## 5. 团队与排期假设

假设：1 名前端、1 名后端全职；产品／设计约 0.5 人；测试约 0.5 人；内容运营 1 人并行。账号申请、内容取得、部署资源由项目方提供。建议 4 周完成 P0，随后 2 周试点；不含无法确定的外部审批等待。

| 阶段 | 任务与交付 | 负责人 | 依赖／验收点 |
|---|---|---|---|
| W1 D1–2 | 确认范围、口径、内容矩阵、部署与微信条件 | 产品＋技术＋运营 | D01–D08 有负责人；无内容组合不展示 |
| W1 D3–5 | 收音机原型、播放器真机验证、匿名身份、内容模型与 API 契约 | 设计＋前后端 | 至少 3 部代表设备完成点击播放、切页、断网恢复验证；首批内容来源可行 |
| W2 | 首页／详情／我的、播放器、选播、内容工作台、8 条内容联调 | 前后端＋运营 | 游客端到端主链路完成；前后端共用契约样例 |
| W3 | 喜欢与偏好、基础分享、反馈、埋点与报表、空态错误态 | 前后端＋测试 | 指标用固定测试事件可复算；行为不重复计数 |
| W4 | 20 条内容、适老测试、真机回归、修复、监控、灰度与回滚演练 | 全体 | P0 验收通过；无阻断缺陷；负责人签署试点放行 |
| W5–6 | 小规模试点、访谈、按设备／内容拆解数据 | 产品＋运营 | 有完整 D1 观察窗口；形成继续／调整／停止结论 |

建议工程工作量：前端 15–19 人日、后端 14–18 人日、测试 6–8 人日、设计／产品 5–7 人日、内容准备 10–15 人日；均为粗估，可并行，不能直接相加当作自然工期。4 周内保留修复余量，W1 后按真实内容与技术验证重估。

P1 微信登录及卡片预计额外前端 2–3、后端 2–3、联调 1–2 人日，外部等待另计。如果项目只有 1 名全栈开发，P0 建议按 6–8 周重排；不能沿用双人并行排期。

关键路径：内容可获得性／播放真机验证 → 播放与选播闭环 → 数据可信性 → 真机与老人试用 → 试点。微信 P1 不阻塞 P0。

## 7. 试点方法与指标定义

建议先用 5–8 位目标年龄用户开展有人观察的可用性测试；修复后邀请约 30–50 位老人试用 14 天。均是建议规模，用于发现方向性问题，不足以证明整体人群需求。记录年龄段、设备、是否由家人帮助首次打开；不采集不必要的生日、定位或联系人。

运营测试、开发账号、陪同演示与自主使用分开标注。匿名身份清除后不可可靠识别同一人，不进行设备指纹补齐；留存结果需披露这一限制。

| 指标 | 统一口径 | 建议观察／门槛 |
|---|---|---|
| 首次打开播放成功率 | 首个 session 中打开后 60 秒内产生 play_started 的新身份数／首个 session 已打开的新身份数 | 先看漏斗，不用点击人群替代全部打开人群 |
| 点击播放成功率 | 用户主动播放尝试后 10 秒内成功的 attempt_id 数／主动尝试数 | 真机技术门槛建议 ≥95%，弱网单列 |
| 自主首播 | 无协助观察用户 30 秒内完成播放的人数／参与观察人数 | 建议 ≥80%，结合失败录像／笔记 |
| 单次收听时长 | session 内所有有效播放增量总和；暂停、缓冲、跳转不计入 | 中位数、P75，初始方向目标中位数 ≥5 分钟 |
| D1 再次打开率 | 首次打开日 D 的身份中，在 D+1 自然日打开的身份数／D 日首次打开且已具完整观察窗口的身份数 | 建议方向目标 ≥25%；同时报告原始人数 |
| D1 再次有效收听率 | 上述分母中 D+1 有效收听累计 ≥30 秒的身份比例 | 与再次打开并列；不把误触当习惯 |
| 年代／类型偏好 | 各维度有效收听秒数、独立听众、每次开始后的平均时长、有效收听转化 | 按曝光量和内容库存解释，不能只按总次数排序 |
| 喜欢率 | 对某节目发生过喜欢设置的独立身份／该节目有效收听 ≥30 秒的独立身份 | 分子限定为分母中的身份；另报当前净收藏数 |
| 换台 | 换台动作数／session；以及播后 30 秒内换出的比例 | 高频可能是探索或不喜欢，结合反馈解读 |
| 反馈 | 喜欢／一般／忽略次数，按曝光为分母 | 不把未反馈算“一般” |

业务时区建议统一 Asia/Shanghai；客户端 UTC 时间入库，按业务时区计算自然日。session：首次进入创建，超过 30 分钟无交互且无播放心跳后结束；持续播放时不因无点击切断。技术上播放成功不等同于用户实际听见，还需现场访谈验证静音／音量问题。

试点结论：技术或内容供给不达标，先修复后重新观察；技术达标但自主使用困难，优先改交互；自主首播顺畅且出现重复有效收听，再决定扩内容与 P1。达到阈值只是继续投入的信号，不是已经验证长期留存。

## 8. 上线门槛与风险处置

- 20 条内容均可播放，来源和展示年代已核查；未通过审核或已下架内容不可进入队列。
- 设备矩阵中的播放、切换、失败恢复、刷新、分享深链全部通过；无白屏、串音、无限自动重试或错误收藏。
- 数据抽样能对账；重复事件不增加时长，客户端关闭允许尾部少量缺失，报表注明计量限制。
- 生产与测试分开，凭证不进入前端，运营写操作有鉴权与审计；隐私说明覆盖实际采集及清除入口。
- 内容供应不足：收缩测试维度，不伪造内容；微信条件不足：关闭 P1 入口并调整“我的”文案；播放器兼容问题：保留点击恢复并阻断有严重问题的平台放量。
- 发布顺序：内部设备 → 小规模观察 → 受邀试点；可通过配置关闭音效、微信能力或问题频道；代码可回滚、数据库变更保持向后兼容、内容可即时下架。

## 9. 需要产品负责人确认的事项

1. 是否接受 D01–D08，尤其暂缓今天／老歌与微信登录。
2. 是否已有可用音频、内容负责人及使用依据，首批 20 条何时具备。
3. 团队配置、目标日期、部署地区／域名，以及目标设备范围。
4. 公众号账号与可用权限由谁核验；未就绪是否按 P0 独立试点。
5. 是否采用上述试点样本与指标初值，谁负责招募与访谈。

这些事项可在范围评审中解决；不妨碍先开展内容盘点、页面原型和播放器真机验证。
