# 声音时间机器｜Codex 开发任务与启动指令

版本：v0.1｜用途：放入项目仓库，让 Codex 按任务实施 MVP。文档本身不代表应用已开发完成。

## 1. 如何放进仓库

建议把 01–05 五份说明放入仓库 `docs/mvp/`，把配套 `AGENTS.md` 作为仓库规则使用。有现有 AGENTS.md 时合并适用规则，保留原有构建、测试、权限及发布规定，不能直接覆盖。没有代码仓库时先创建空项目目录并初始化 git，再由 Codex 执行下面的启动指令。

现有项目优先沿用技术栈。空仓库的默认实现方案为：前端 React＋TypeScript＋Vite，后端 Node.js＋TypeScript＋Fastify，数据库 PostgreSQL；前后端同仓库、使用 npm workspaces。具体稳定版本由开发时依据官方文档与运行环境确认，提交 lockfile。此选择是执行默认值，不是现有项目情况。

结构建议：

| 路径 | 用途 |
|---|---|
| `apps/web/` | H5 与轻量运营 UI，路由和权限分开 |
| `apps/api/` | HTTP API、业务服务、数据库访问 |
| `packages/contracts/` | API 类型、校验 schema、共享枚举与事件名 |
| `docs/mvp/` | 01–05 产品与开发规格 |
| `docs/openapi.yaml` | 实际实现维护的完整接口契约 |
| `docs/progress.md` | 每个任务的状态、验证证据、限制与下一步 |
| `docs/decisions.md` | 实施假设、范围差异和关键选择 |
| `infra/` | 本地数据库启动配置与部署样例 |

媒体存储封装为 adapter；本地用受控测试目录或开发存储，生产接对象存储。不要因为没有云服务密钥而停止本地闭环；也不要把本地存储当成已完成的生产接入。

## 2. 给 Codex 的首次启动指令

下面整段可直接复制到已放入这些文件的 Codex 项目会话：

```text
请按 AGENTS.md 和 docs/mvp/ 下 01–05 文档开发“声音时间机器”MVP。

先检查仓库已有代码、AGENTS.md、依赖和运行命令，保留用户已有修改。
不要只输出方案，要完成代码、数据库迁移、接口契约和必要验证。

采用文档中的 MVP 默认方案：游客直接收听；三个主入口；只开放有内容的年代和类型；喜欢包含持久化状态和列表；微信登录和 SDK 卡片为 P1，缺凭证时关闭入口并保持 P0 可运行。
这些默认值可用于本次实现；常规实现细节自行决定并记录。不得自行扩展 AI 陪伴、推荐、支付或社交。

如果是空仓库，按 05 的默认技术方案建立项目；有既有项目则沿用既有技术栈并记录差异。
先完成 C00–C02，再依序推进 C03–C09。每步必须有可运行交付和相应验收，不得用静态界面、永久 mock 或假的成功响应代替业务功能。
外部内容或账号缺失时，使用明确标注的开发 fixture 继续本地开发，记录生产阻塞项；不得伪造授权资源、真机验证或用户试点结果。

每完成一个任务更新 docs/progress.md，写明修改内容、运行命令、实际验证结果、尚未验证的部分。只有出现无法安全推断且阻断核心实现的问题时再提问；不要为常规可逆实现反复确认。
不要部署到生产、对外发布或创建付费资源。本轮目标是本地可运行、可验证的 P0 开发版本；完成后给出启动步骤、验收结果和上线前剩余依赖。
```

该指令将规划中的“建议默认值”明确转为开发执行基线。产品负责人如果要保留今天／老歌或首发微信，应先改对应范围条目，避免一边实现一边采用两套口径。

## 3. 统一执行与完成规则

每个任务流程：读取对应章节 → 检查已实现部分 → 列出最小改动 → 实现 → 验证关键行为 → 更新契约与进度。不要每次从头搭项目，不要重写已经通过验收的模块。

开发 fixture 至少包含：不同年代与类型、一个空组合、单条组合、多条组合、一条下架节目、一条 AI 重制标识样例。fixture 标题须含“开发示例”，不使用真实经典作品名制造有资源的假象。测试音频使用可合法使用的样本或明确标注的合成测试音；用于测试的音频不能计入真实 20 条内容。

验收分两层：自动验证与本地操作通过可以标为“开发完成”；20 条真实内容、目标真机、老人试用、生产配置未具备时只能标为“待上线验收”，不能宣称已上线。某任务未通过则修复，不用删除测试、降低断言或改规格把错误变成成功。

根目录应提供并验证：`npm run dev`、`npm run build`、`npm run typecheck`、`npm test`、`npm run db:migrate`、`npm run db:seed`。这是空仓库要求；现有仓库使用原有等价命令并在 README 记录。数据库启动命令由实际工具决定，不假装环境已安装 Docker。

## 4. 可直接执行的开发任务

### C00｜仓库检查、范围与契约骨架

输入：01 全文、04 枚举／接口、当前仓库。

实现：检查既有结构与改动；确定沿用栈或空仓默认栈；创建 progress、decisions；建立共享枚举、错误结构与 OpenAPI 初稿；列出外部依赖但先不接入。

验收：数据类型统一用毫秒；没有 today/music 的已启用选项；P0/P1 开关明确；接口示例与 OpenAPI 一致，尚未实现的接口有明确标记。

依赖：无。不得在此任务停留于再次生成规划而不进入 C01。

### C01｜项目启动、数据库与测试夹具

输入：03 架构、04 数据模型。

实现：建立可运行前后端和数据库连接；迁移身份、偏好、媒体、节目、来源／审核、运营账号等基础表；本地种子数据；`.env.example` 与启动 README；测试与生产数据隔离。提供最小健康接口和必要错误页。

验收：新数据库可迁移、可幂等 seed；前后端启动；构建和类型检查通过；密钥不提交；fixture 不能默认发布到生产环境。

依赖：C00。

### C02｜真实媒体播放技术纵切

输入：02 首播与错误态、03 播放器状态机。

实现：单个全局 audio；最小首页从实际 API 获得已发布 fixture 元信息与媒体，用户点击能播放／暂停；实现策略受阻、媒体加载失败、重试、切路由不重建 audio；建立 playback/attempt 契约。自动浏览器验证可作为补充。

验收：本地真实发声或可观察媒体 currentTime 推进，按钮状态正确；错误地址有恢复；同一音频不叠加。实际 iOS／Android／微信未验证时显式记录，不用桌面结果代替。

依赖：C01。此项用于尽早发现媒体问题，应先于大量视觉细节。

### C03｜匿名身份、内容矩阵与队列

输入：03 选播／身份、04 对应表和 API。

实现：游客 cookie、会话、偏好读写、catalog、队列创建与 next；事务消费、幂等请求、去重洗牌、下架过滤、过期重建；身份隔离。

验收：0／1／多条候选得到正确结果；同 request_id 不重复消费；快速切换只应用最后选择；不同主体无法读取队列；游客刷新偏好保留。

依赖：C01–C02。

### C04｜完整适老页面与收听闭环

输入：02 全文。

实现：今日电台、年代声音、播放详情、我的、偏好、隐私路由；三主入口；明确确认后再切年代；播放结束接播与单条停止；迷你播放器；大字号、大按钮、窄屏与错误态；电流音默认关闭。

验收：首访不登录不做问卷即可发起播放；切页不断音；分享详情与全局当前节目不同也不误切；放大文字和小屏无关键控件遮挡；不存在无内容却可点击的空承诺入口。

依赖：C02–C03。视觉可以复古，但不能用不可操作的旋钮图片代替真实按钮。

### C05｜喜欢、轻反馈、基础分享与数据清除

输入：02 第 5–8 节、04 对应关系与 API。

实现：幂等喜欢／取消、列表和下架占位；不遮挡播放的反馈及频控；节目深链、产品链接、复制与微信内指引；退出与数据清除及本地待发队列清理。

验收：喜欢刷新存在、失败回滚；反馈绑定原节目；分享接收者可直达并点击播放；没有实际发送成功的伪埋点；不同主体不能删别人的数据；清除后不自动重传旧事件。

依赖：C03–C04。

### C06｜可信采集、统计与导出

输入：01 指标、03 时长、04 埋点与复算样例。

实现：事件白名单、批量去重、播放进度单调累计、跨日归档与限制标注、分析开关；日报与 CSV；排除测试数据；喜欢当前数与历史行为分开。

验收：04 的固定样例计算结果一致；暂停／缓冲／seek 不增加有效时长；重复／乱序不多计；完整 D1 窗口才纳入分母；关闭分析不继续保存长期收听事件；CSV 无身份凭证且防公式注入。

依赖：C03–C05。若实装细节需要细化 04，先记录一致的新规则并同步测试，不可偷偷改口径。

### C07｜轻量运营内容工作台

输入：01 内容工作包、03 内容管理、04 运营接口。

实现：独立运营鉴权、受控上传、实际媒体校验、节目编辑、送审、审核、发布、下架、审计；页面中标注原声／现代演绎／AI 重制；运营日报入口。

验收：游客不能调用任何写接口；审核缺资料不能发布；换音频需重审；下架后新队列和新播放不能再选；上传失败可恢复；并发编辑有版本冲突处理。

依赖：C01 的模型，可在主流程完成后集中交付；不得以开发直写数据库作为最终运营能力。

### C08｜集成验收与发布准备

输入：01 上线门槛、02 验收、03 测试矩阵。

实现：核心 E2E、针对性异常测试、错误与指标日志、配置开关、备份／回滚说明；清理误导文案；记录媒体有效期及下架限制；完整 README。

验收：干净环境按 README 能启动；关键接口有鉴权测试；全部 P0 流程通过可执行测试；真实内容和真机缺项单独记录。只完成准备，不自动发布公网或申请付费资源。

依赖：C04–C07。

### C09｜交付报告与试点阻塞清单

实现：汇总每项完成状态、测试命令与实际结果、未验证平台、真实内容数量、微信能力状态、生产配置及后续操作；核对文档与代码一致。

验收：明确区分“已运行”“已测试”“尚未验证”；不存在把 fixture 当成 20 条真实内容、把链接复制当成分享发送、把桌面测试当成老人试用的表述。

依赖：C08。完成此项代表本轮 Codex P0 开发交付，不代表完成 W5–6 真实试点。

### C10｜微信账号绑定与卡片（P1，单独开启）

前置：实际账号权限、域名与必要凭证已具备并被安全配置，用户要求实施 P1。

实现：服务端授权、state 校验、游客合并、退出隔离、SDK 配置、分享卡片降级。不得猜测权限或写死伪造身份。

验收：成功／取消／失败／重复回调／同设备换账号均通过；没有密钥进入前端；基础分享和游客主流程不依赖 P1 成功。

## 6. 单任务执行指令

```text
请完成任务 C05（或替换成目标任务 ID）。先读取任务列出的输入文档及现有实现，只补齐此任务缺失部分。
实现业务代码、接口和必要迁移，执行该任务的验收；保持其他已完成流程可用。完成后在 docs/progress.md 记录证据与限制，并说明下一项依赖是否满足。不要自动实施 P1 或部署生产。
```

若要让 Codex 长时间连续开发，使用首次启动指令；若需要逐次评审，则使用单任务指令。两种方式共享任务顺序与完成标准。
